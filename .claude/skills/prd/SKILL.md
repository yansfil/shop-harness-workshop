요청: $ARGUMENTS

PRD는 구현의 계약이면서 독립 검증의 채점표입니다. 코드는 쓰지 않습니다.

1. 루트 `CLAUDE.md`, `docs/rules/`, 관련 코드·테스트를 읽습니다. `docs/tasks/<slug>.interview.md`가 있으면 먼저 읽습니다.
2. `references/prd-template.md`의 틀로 `docs/tasks/<slug>.md`를 씁니다. 인터뷰의 결정·비범위·미해결 항목을 빠짐없이 옮깁니다.
3. 완료 조건(AC)마다 "상황·입력 → 행동 → 관찰할 수 있는 결과"를 씁니다. 정상 흐름뿐 아니라 권한, 빈 상태, 경계 값, 거절, 복구를 고릅니다. 기대값은 사용자 결정과 규칙 문서에서 가져오고 현재 구현의 출력을 복사하지 않습니다.
4. 비범위와 보존 동작(바뀌면 안 되는 것)을 적습니다. 검증 범위 표에 tests·api·ui를 required 또는 not-applicable로 적고 이유를 씁니다.
5. 제품 판단이 남으면 한 번에 하나씩 묻고 `확정 여부: **초안**`을 유지합니다. 사용자 답변과 기존 계약이 근거를 줄 때만 `**확정**`으로 바꿉니다. 에이전트의 제안을 사용자 승인으로 적지 않습니다.
6. 구현은 하지 않습니다. 확정되면 `implement` Skill로 이어 가도록 PRD 경로를 알립니다.

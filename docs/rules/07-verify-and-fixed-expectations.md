# 7. 완료 전 verify, 테스트 기대값 고정

작업을 끝냈다고 말하기 전에 `npm run verify`를 돌려 통과를 확인합니다.
기존 테스트가 실패하면 코드를 고칩니다.
기존 테스트의 기대값(`expect(...)`의 값)을 바꿔서 통과시키지 않습니다.

## 이유

`npm run verify`는 Node 24 확인 → 타입 검사 → lint → 테스트 → 빌드를 Mac·Windows에서 같게 돌립니다.
테스트 일부만 돌리거나 빌드를 건너뛰면 다른 사람 노트북에서 깨지는 변경이 들어옵니다.
기존 기대값은 이미 합의된 동작입니다.
기대값을 바꾸면 테스트는 초록색이 되지만 사용자가 보는 동작이 몰래 바뀝니다.
동작을 정말 바꿔야 하면 그 결정을 먼저 사람에게 확인받고, 새 동작을 새 테스트로 적습니다.

## 좋은 예

```
$ npm run verify
...
[verify] 통과: Node 24 확인 → 타입 검사 → lint → 테스트 → 빌드
```

## 나쁜 예

```diff
- expect(order.total).toBe(15900);
+ expect(order.total).toBe(12900);
```

계산이 바뀌어 테스트가 깨졌는데 기대값을 새 결과에 맞춰 고친 경우입니다.

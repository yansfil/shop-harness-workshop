# free-shipping-threshold

확정 여부: **확정**

무료배송 기준을 30,000원에서 50,000원으로 올리고, 배송비가 붙는 견적에는 무료배송까지 남은 금액을 안내한다.
인터뷰 기록: `docs/tasks/free-shipping-threshold.interview.md`, 규칙이 쓰이는 곳: `docs/tasks/shipping-fee-rule.md`

## 문제 / 범위

- 상품 합계가 50,000원 이상이면 배송비 0원, 미만이면 3,000원이다(기준만 바뀌고 배송비 금액은 그대로다).
- 견적 응답(`POST /api/orders/quote`)에 `freeShippingRemaining`(무료배송까지 남은 금액, 정수 원)을 더한다. 이미 무료면 0이다.
- 장바구니와 주문서의 금액 요약은 배송비가 붙을 때만 "N원 더 담으면 무료배송"을 보인다.

## 비범위 / 보존 동작

- 배송비 금액(3,000원), 결제 금액 = 상품 합계 + 배송비 계산식, 견적과 주문 생성이 같은 함수를 쓰는 구조는 그대로다.
- 이미 만든 주문의 배송비·결제 금액은 저장된 값 그대로다. 주문 응답 모양은 바뀌지 않는다.
- 상품 상세의 배송비 표시, 검색의 "3만원 이상" 가격 구간은 그대로다.
- 도서산간·카테고리별 배송비 같은 새 규칙은 이번 범위가 아니다.
- DB 스키마와 마이그레이션은 바뀌지 않는다.

## 결정

| ID | 결정 | 근거 |
| --- | --- | --- |
| D-1 | 기준은 상품 합계 50,000원 이상 무료, 미만 3,000원이다 | 인터뷰 D-1 |
| D-2 | 기존 주문의 배송비는 다시 계산하지 않는다 | 인터뷰 D-2 |
| D-3 | 남은 금액은 서버가 `Money`로 계산해 견적 응답에 담고 화면은 그대로 보인다 | 인터뷰 D-3, `docs/rules/02-money-integer-won.md`, `apps/web/CLAUDE.md` |
| D-4 | 규칙은 `shipping-fee.ts` 한 곳에만 둔다. 화면에 기준 금액을 쓰지 않는다 | `docs/tasks/shipping-fee-rule.md` |

## 완료 조건

| ID | 상황·입력 → 행동 → 관찰할 결과 | 확인 방법 |
| --- | --- | --- |
| AC-1 | 상품 합계 48,700원 장바구니를 견적하면 `shippingFee: 3000`, `total: 51700`, `freeShippingRemaining: 1300`이다 | API 통합 테스트 `tests/orders.test.ts` |
| AC-2 | 상품 합계가 정확히 50,000원이면 `shippingFee: 0`, `freeShippingRemaining: 0`이다 | API 테스트(5,000원 상품 10개) |
| AC-3 | 상품 합계 30,000원 이상 50,000원 미만(예전에는 무료였던 구간)은 배송비 3,000원이다 | API 테스트 |
| AC-4 | 주문을 만들면 견적과 같은 배송비가 주문에 저장되고, 이후 주문 조회는 저장된 값을 그대로 돌려준다 | API 테스트 |
| AC-5 | 요약 상자는 `freeShippingRemaining`이 0보다 크면 "N원 더 담으면 무료배송"을 보이고, 0이면 보이지 않는다 | 컴포넌트 테스트 |
| AC-6 | 기존 테스트의 기대값은 그대로 통과한다(합계 50,700원 주문은 여전히 무료, 합계 10,000원은 3,000원) | `npm run verify` |

# order-cancel

확정 여부: **확정**

고객이 결제완료·배송준비 상태의 내 주문을 취소하고, 주문한 재고가 되돌아온다.
인터뷰 기록: `docs/tasks/order-cancel.interview.md`

## 문제 / 범위

지금은 주문을 만든 뒤 고객이 취소할 방법이 없다. 잘못 주문하면 관리자에게 따로 부탁해야 하고, 재고는 되돌릴 길이 없다.

- 고객은 내 주문 상세에서 "주문 취소" 버튼을 눌러, 확인 창을 거쳐 주문을 취소한다.
- 취소한 주문의 상태는 `cancelled`("주문취소")이고, 주문 품목 수량만큼 재고가 늘어난다.
- 재고가 늘 때마다 입출고 이력에 "취소 복구" 한 줄이 주문 번호와 함께 남는다.
- 주문 응답은 취소할 수 있는지(`cancellable`)를 서버가 계산해 담는다.
- 관리자 주문 목록과 상세는 취소된 주문을 뱃지로 보이고 다음 단계 버튼을 보이지 않는다.

## 비범위 / 보존 동작

- 관리자가 대신 취소하는 기능, 부분 취소, 취소 사유 입력은 없다.
- 쿠폰·포인트·실제 환불은 없다(이 레포에 없다).
- 배송중·배송완료 주문은 취소할 수 없다.
- 주문 생성·견적·재고 차감·입고의 동작은 그대로다. 기존 테스트의 기대값은 바뀌지 않는다.
- 관리자의 상태 변경(`POST /api/admin/orders/:orderId/status`)은 지금처럼 다음 단계로만 넘기고, `cancelled`로는 바꿀 수 없다.
- 남의 주문은 지금처럼 찾을 수 없다고 나온다(404).

## 결정

| ID | 결정 | 근거 |
| --- | --- | --- |
| D-1 | 취소할 수 있는 상태는 `paid`(결제완료)와 `preparing`(배송준비)뿐이다 | 인터뷰 D-1 |
| D-2 | 주문한 고객 본인만 취소한다. 고객은 세션에서만 정한다 | 인터뷰 D-2, `docs/rules/05-customer-id-from-session.md` |
| D-3 | 재고 복구는 `InventoryService`의 새 메서드로만 한다. 상태 변경과 재고 복구는 한 트랜잭션이다 | 인터뷰 D-3, `docs/rules/01-inventory-service-only.md` |
| D-4 | 새 상태 `cancelled`로의 전이는 orders 도메인의 전이 함수 한 곳이 정한다 | `docs/rules/03-order-status-transition.md` |
| D-5 | 이미 취소된 주문을 다시 취소하면 200으로 같은 주문을 돌려주고 재고는 다시 늘리지 않는다 | 인터뷰 D-5 |
| D-6 | 입출고 이력에 `restock`(취소 복구) 종류를 더한다. 기존 `CHECK` 제약을 넓히려면 새 번호 마이그레이션 `0002`가 필요하다 | `docs/rules/08-new-numbered-migration.md` |
| D-7 | `cancellable`은 서버가 계산해 응답에 담고 화면은 그대로 쓴다 | `.claude/rules/contracts.md` |
| D-8 | 취소할 수 없는 상태에서 요청하면 409 `ORDER_NOT_CANCELLABLE`이다 | 인터뷰 D-1 |

## 완료 조건

| ID | 상황·입력 → 행동 → 관찰할 결과 | 확인 방법 |
| --- | --- | --- |
| AC-1 | 결제완료 주문을 고객이 `POST /api/orders/:orderId/cancel`로 취소하면 200이고 `status: "cancelled"`, `cancellable: false`다 | API 통합 테스트 `tests/orders.test.ts` |
| AC-2 | 취소하면 주문 품목마다 재고가 그 수량만큼 늘고, 입출고 이력에 `restock` 한 줄(양수, 주문 번호 포함)이 남는다 | API 테스트(재고 목록과 이력 조회) |
| AC-3 | 배송준비 주문도 취소된다 | API 테스트(관리자가 한 단계 넘긴 뒤 취소) |
| AC-4 | 배송중·배송완료 주문을 취소하면 409 `ORDER_NOT_CANCELLABLE`이고 주문 상태와 재고는 그대로다 | API 테스트 |
| AC-5 | 이미 취소된 주문을 다시 취소하면 200이고 재고는 한 번만 늘어난 그대로다 | API 테스트 |
| AC-6 | 남의 주문 취소는 404, 로그인하지 않으면 401, 관리자 계정은 403이고 재고는 그대로다 | API 테스트 |
| AC-7 | 관리자가 상태 변경으로 `cancelled`를 보내면 409이고 주문과 재고는 그대로다 | API 테스트 |
| AC-8 | 주문 조회 응답의 `cancellable`은 결제완료·배송준비면 true, 그 밖(배송중·배송완료·취소)이면 false다 | API 테스트 |
| AC-9 | 내 주문 상세에서 취소할 수 있는 주문에만 "주문 취소" 버튼이 있고, 누르면 확인 창이 뜬다. 확인하면 상태가 "주문취소"로 바뀌고 버튼이 사라진다. 확인 창에서 닫으면 아무것도 바뀌지 않는다 | 컴포넌트 테스트 |
| AC-10 | 취소 요청이 실패하면 이유가 화면에 보이고 주문은 그대로 보인다 | 컴포넌트 테스트 |
| AC-11 | 관리자 주문 목록·상세는 취소된 주문을 "주문취소" 뱃지로 보이고 다음 단계 버튼이 없다 | 컴포넌트 테스트 |
| AC-12 | 관리자 재고 화면의 입출고 이력에 "취소 복구" 줄이 주문 번호와 함께 보인다 | 컴포넌트 테스트 |
| AC-13 | `0002` 마이그레이션이 새 DB와 기존 DB(0001만 적용)에서 모두 적용되고 기존 이력 행이 그대로 남는다 | `packages/db/src/migrate.test.ts` |
| AC-14 | 기존 테스트의 기대값은 그대로 통과한다 | `npm run verify` |

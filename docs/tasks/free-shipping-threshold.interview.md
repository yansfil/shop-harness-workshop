# free-shipping-threshold 인터뷰

요청: 무료배송 기준을 50,000원으로 올려 주세요.
상태: **PRD-ready**

현재 코드에서 본 사실: 상품 합계가 30,000원 이상이면 배송비 0원, 미만이면 3,000원이다. 규칙은 `apps/api/src/orders/domain/shipping-fee.ts` 한 곳이고, 견적과 주문 생성이 같은 함수를 쓴다.
배송비는 주문 시점 값이 `orders.shipping_fee`에 저장된다.
`docs/tasks/shipping-fee-rule.md`가 이 규칙을 쓰는 곳을 적어 두었다.

## 질문과 답

| 번호 | 질문 | 답 |
| --- | --- | --- |
| D-1 | 기준 금액에 딱 맞으면 무료인가요? | 50,000원 이상이면 무료, 미만이면 지금처럼 3,000원. 배송비 금액은 그대로다 |
| D-2 | 이미 만든 주문의 배송비는요? | 바꾸지 않는다. 주문에 저장된 값을 그대로 보인다 |
| D-3 | 기준이 올라 고객이 헷갈리지 않게 안내가 필요한가요? | 배송비가 붙는 장바구니·주문서에 "N원 더 담으면 무료배송"을 보인다. N은 서버가 계산해서 준다 |
| D-4 | 상품 목록·검색의 "3만원 이상" 가격 구간은요? | 가격 필터라 배송비와 별개다. 그대로 둔다 |
| D-5 | 시드 주문과 시뮬레이터 주문은요? | 같은 주문 서비스를 거치므로 `npm run db:reset`으로 다시 만들면 새 기준으로 계산된다. 의도한 변화다 |
| D-6 | DB 스키마는요? | 바꾸지 않는다. 마이그레이션 없음 |

## 미해결

없음. `prd` Skill로 이어 간다.

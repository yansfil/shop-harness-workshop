# low-stock-alert

확정 여부: **확정**

관리자가 재고 화면에서 안전재고 미만 상품을 바로 알아볼 수 있게 한다.
`implement` Skill로 구현하고 `verifier`로 검증하는 연습용 PRD다.

## 문제 / 범위

상품마다 안전재고(`inventory.safety_stock`)가 DB에 있지만 어느 화면과 API에도 나오지 않는다.
관리자는 재고 대시보드의 수량 숫자를 하나씩 읽어 부족한 상품을 찾아야 한다.

- 재고 API(`GET /api/admin/inventory`, 이력 응답의 `item`, 입고 응답의 `item`)가 상품마다 `safetyStock`과 `lowStock`(안전재고 미만 여부)을 준다.
- 관리자 재고 화면이 안전재고 미만 상품을 뱃지로 표시하고, 위쪽에 "안전재고 미만 N개" 알림 줄을 보인다.
- 알림 줄을 누르면 목록이 안전재고 미만 상품만 보이는 필터로 바뀌고, 다시 누르면 전체로 돌아온다.
- 입고를 등록해 수량이 안전재고 이상이 되면 뱃지와 알림 개수가 바로 줄어든다.

## 비범위 / 보존 동작

- 고객 화면의 "남은 수량 적음"(재고 5개 이하)은 그대로다. 안전재고와 별개의 기준이다.
- 이메일·푸시·자동 발주 같은 외부 알림은 하지 않는다.
- 안전재고 값을 화면에서 고치는 기능은 없다. 값은 지금처럼 시드가 정한다.
- 주문·입고·이력의 동작과 응답의 기존 필드(`productId`, `productName`, `categoryName`, `quantity`, `updatedAt`)는 바뀌지 않는다.
- 관리자가 아닌 계정은 지금처럼 재고 API를 쓸 수 없다.

## 결정

| ID | 결정 | 근거 |
| --- | --- | --- |
| D-1 | 안전재고 미만은 `quantity < safetyStock`이다. 안전재고와 같으면 미만이 아니다 | 사용자 결정 |
| D-2 | 품절(`quantity = 0`)도 안전재고 미만이다. 화면은 품절 상품을 같은 뱃지로 보인다 | 사용자 결정 |
| D-3 | `lowStock`은 서버가 계산해 응답에 담는다. 화면이 비교하지 않는다 | `docs/rules`의 계층 규칙, 화면은 파생 상태를 계산하지 않는다 |
| D-4 | 새 DB 컬럼은 없다. `safety_stock`은 이미 있으므로 마이그레이션을 추가하지 않는다 | `docs/rules/08-new-numbered-migration.md` |
| D-5 | 필터와 알림 줄은 브라우저 화면 상태다. 주소나 저장소에 남기지 않는다 | 사용자 결정 |

현재 코드에서 본 사실: 재고 조회 SQL(`sqlite-inventory-repository.ts`의 `ITEM_SELECT`)은 `safety_stock`을 읽지 않고, 계약(`packages/contracts/src/inventory.ts`)의 `InventoryItemSchema`에도 필드가 없다.

## 완료 조건

| ID | 상황·입력 → 행동 → 관찰할 결과 | 확인 방법 |
| --- | --- | --- |
| AC-1 | 안전재고 10, 수량 9인 상품을 관리자가 `GET /api/admin/inventory`로 조회하면 그 상품은 `safetyStock: 10`, `lowStock: true`다 | API 통합 테스트(`tests/inventory.test.ts`) |
| AC-2 | 수량이 안전재고와 같거나 많은 상품은 `lowStock: false`다 | 경계 값 10 대 10, 10 대 11 테스트 |
| AC-3 | 수량 0인 상품은 `lowStock: true`다 | API 테스트 |
| AC-4 | 안전재고 미만 상품에 입고를 등록해 수량이 안전재고 이상이 되면, 입고 응답의 `item.lowStock`이 `false`이고 이어서 목록을 조회해도 `false`다 | API 테스트 |
| AC-5 | 재고 화면에서 안전재고 미만 상품 행에 "안전재고 미만" 뱃지가 있고, 아닌 행에는 없다 | 컴포넌트 테스트 또는 화면 확인 |
| AC-6 | 안전재고 미만이 N개(N ≥ 1)이면 목록 위에 "안전재고 미만 N개" 알림 줄이 있고, 0개면 알림 줄이 없다 | 컴포넌트 테스트 |
| AC-7 | 알림 줄을 누르면 안전재고 미만 상품만 보이고, 다시 누르면 전체 목록으로 돌아온다 | 컴포넌트 테스트 |
| AC-8 | 필터가 켜진 채 입고로 한 상품이 안전재고 이상이 되면 그 행이 목록에서 사라지고 알림 개수가 1 줄어든다 | 컴포넌트 테스트 |
| AC-9 | 고객 계정과 로그인하지 않은 요청은 지금처럼 거절되고(403·401), 기존 필드와 기존 테스트의 기대값은 그대로 통과한다 | 기존 `tests/inventory.test.ts`, `npm run verify` |
